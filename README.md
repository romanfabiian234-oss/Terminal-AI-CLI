# Terminal AI CLI

Лёгкий локальный терминал с лентой блоков в духе Codex CLI: **объяснение выше, исходный технический вывод ниже**. Исходный вывод остаётся доступен. Блоки не дублируются при обновлениях. Это **ранняя тестовая версия v0.1**, а не замена полноценному эмулятору терминала.

## Что уже работает

- Терминальный TUI на `curses`: при запуске **чистый экран и обычное приглашение** `имя-компьютера ~/путь %` без цветного заголовка и стартового блока. После ввода команды появляется блок с объяснением и техническим выводом; строка ввода идёт сразу после него (при длинной истории фиксируется внизу). Заголовки блоков — немного насыщеннее зелёным, галочка остаётся ярко-зелёной. Приглашение использует синий ANSI-256 №75 (при поддержке 256 цветов), близкий к стандартному цвету Zsh на Mac. Технический вывод **всегда полностью раскрыт по умолчанию** (например, все 150 строк `seq 1 150` доступны сразу через прокрутку); `Ctrl+T` можно использовать только при желании свернуть/развернуть. Поддерживается история.
- Интерфейс работает в отдельном **alternate screen buffer**: скроллинг не должен показывать старый вывод обычного Terminal внутри приложения. После `codex` / `vim` приватный экран восстанавливается. Старая история Terminal не стирается и остаётся доступной после выхода. Внутренняя история: `PageUp` / `PageDown`; колёсико мыши зависит от терминального эмулятора.
- Запуск реальных команд через PTY. Вывод обновляется по мере появления; ошибка определяется по коду завершения, а не по догадке модели. Пока команда выполняется, результат не объявляется успешным или ошибочным. В блоках `PAGER=cat` и `GIT_PAGER=cat` отключают интерактивный просмотрщик Git; для него остаётся `/raw`.
- **Безопасная вставка из буфера обмена:** включён bracketed paste (`ESC[200~` / `ESC[201~`). Вставка даже из нескольких строк **ничего не запускает сама**. Первая строка появляется в редактируемом приглашении, **все остальные команды сразу видны под ней** (если их много, показывается количество скрытых строк). Каждая команда запускается только отдельным нажатием **Enter**. `Ctrl+C` отменяет оставшиеся непроверенные команды. Учитываются ограничения количества и размера команд и отклоняются управляющие символы. Быстро набранные вручную команды с Enter по-прежнему ставятся в очередь до 32 команд. Для передачи ввода активной программе (например, `read`) нажмите `Ctrl+G`. В режиме `/raw` управление вставкой передаётся дочернему приложению. Если эмулятор терминала не поддерживает bracketed paste, отличить вставленный Enter от ручного без отдельного подтверждения невозможно; функция требует реальной проверки в Terminal.app.
- **Экспериментальная постоянная сессия** `/session on`: отдельные команды работают в одной Bash/Zsh-оболочке, сохраняются `cd`, переменные, функции и алиасы. На Linux/Bash прошла тестирование; macOS/Zsh ещё нужно проверить.
- Мгновенные объяснения стандартных действий через правила: `ls`, `pwd`, `date`, `git status` и `git log` не вызывают модель без необходимости. Опциональные объяснения локального ИИ и fallback при недоступном сервере.
- **Произвольные модели через Ollama** и модели на **OpenAI-совместимых HTTP API** (например, LM Studio, llama.cpp, vLLM). Сервер может быть на Mac, домашней машине или удалённым.
- Разные профили и переключение командой `/model`; ключи API только из переменных окружения, HTTPS для удалённых серверов по умолчанию.
- При вводе `codex`, `codex resume`, `vim`, `nvim`, `nano`, `htop`, `btop` программа автоматически переключается в полноценный экранный режим: ввод, стрелки, цвета и перерисовка работают напрямую. Для других программ доступно `/raw COMMAND`. После выхода показывается **короткий блок с кодом завершения**, без захламления истории фрагментами перерисованного экрана. Содержимое полноэкранного интерфейса не отправляется ИИ и не сохраняется в журнале. Для `codex exec` и составных shell-команд используется обычный режим блоков. Во время интерактивного режима AI-пояснения **пока не выводятся**.
- История выводов хранится **только в RAM** в ограниченных буферах; нет телеметрии, встроенного облачного сервиса и автоматического выполнения AI-команд.

## Установка (macOS)

Требуется Python **3.11+**, macOS и встроенный `/bin/zsh`. Для базовой версии не требуется установка Rust, tmux или Ollama (если AI отключён).

```bash
# Из папки, в которую удобно клонировать проекты:
git clone https://github.com/romanfabiian234-oss/Terminal-AI-CLI-.git
cd Terminal-AI-CLI-
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
terminal-ai init
terminal-ai doctor
terminal-ai
```

Для локального ИИ отдельно установите и запустите Ollama и загрузите нужную модель:

```bash
ollama pull qwen3.5:2b
```

Если Python 3.11+ отсутствует, установите актуальный Python отдельно. Не запускайте скрипты установки с неизвестных сайтов.

`terminal-ai` — новая программа внутри обычного терминального окна (Terminal.app, iTerm2, Ghostty). Она **не заменяет системный Terminal.app**.

## Управление

Команды приложения начинаются с `/`, как в Codex CLI. Старый префикс `:` временно сохраняется для совместимости. Обычные пути, например `/bin/echo`, выполняются как команды оболочки.

`/explain` создаёт **новый видимый блок** с ответом ИИ о последней выполненной команде; при отсутствии связи с моделью показывает ошибку, а не молчит. При обращении к модели рядом с блоком показываются **реальное имя модели, профиль и время ответа** (от начала запроса в обработчике до завершения, включая ожидание первого токена; это не отдельный замер скорости токенов). Обычные команды с правилами не притворяются результатами ИИ. Известные ошибки Python, отсутствие прав/файла и отсутствие Git-репозитория получают более конкретное объяснение даже без модели.

| Действие | Команда |
| --- | --- |
| Помощь | `/help` |
| Постоянная оболочка (экспериментально) | `/session on` / `/session off` |
| Список профилей | `/models` |
| Выбор модели/сервера | `/model local` или `/server home` |
| Повторно объяснить последнюю операцию | `/explain` |
| Язык новых объяснений | `/language ru`, `/language uk`, `/language en` |
| Включить или выключить ИИ | `/ai on` / `/ai off` |
| Необязательно свернуть или развернуть полный вывод последнего блока | `Ctrl+T` или `/expand` |
| Прокрутить ленту | `PageUp` / `PageDown` |
| Очистить историю в RAM | `Ctrl+L` или `/clear` |
| Прямой PTY-режим для TUI | `/raw codex` / `/raw vim` |
| Перейти в другую папку | `cd path` |
| Выйти | `/exit` или `Ctrl+D` на пустой строке |

Во время обычной выполняемой команды ввод **не передаётся** ей автоматически: новый текст считается следующей командой и попадает в очередь. Для `codex` и других перечисленных полноэкранных программ ввод сразу передаётся напрямую; специальная команда `/raw codex` больше не обязательна. `Ctrl+G` переключает прямую передачу ввода/очередь; `Ctrl+C` прерывает процесс и очищает очередь. `/raw` даёт дочерней программе прямое управление экраном; по завершении следует нажать Enter для возврата к ленте.

**Ограничения:** по умолчанию каждая обычная команда запускается в отдельной сессии `zsh -lc`; сохраняется `cd`, но не переменные, функции и алиасы между такими командами. При `/session on` запускается **постоянная** интерактивная `zsh -ic` (или выбранная оболочка), где сохраняется состояние; сейчас принимаются только **однострочные команды**, а shell-режимы Bash и Zsh могут отличаться. Проверено с Bash на Linux, но не с Zsh на macOS. В экспериментальной сессии `Ctrl+C` завершает внешнюю foreground-программу сигналом `SIGTERM` (не `SIGINT`), чтобы сохранить состояние оболочки; при прерывании shell builtins она всё ещё может завершиться. В режиме `/raw` запускается отдельная интерактивная программа, не использующая состояние предыдущей сессии. Для сложных полноэкранных TUI ещё нет надёжной реконструкции визуальных действий. Полное объединение пояснений с внутренними блоками Codex — следующий этап, не готовая функция.

## Подключение моделей и сервера

Файл: `~/.config/terminal-ai/config.toml` (создаётся через `terminal-ai init`). Пример:

```toml
[app]
language = "ru"
shell = "/bin/zsh"
max_blocks = 100
max_output_lines = 400

[models]
active = "local"

[models.local]
provider = "ollama"
base_url = "http://127.0.0.1:11434"
model = "qwen3.5:2b"

[models.home]
provider = "openai"
base_url = "https://my-ai-server.example/v1"
model = "any-model-on-server"
api_key_env = "TERMINAL_AI_KEY"
allow_remote = true
```

`provider = "ollama"` использует `/api/chat`; `provider = "openai"` использует `/chat/completions`. API-ключ указывать через `export TERMINAL_AI_KEY=...` **на своём Mac, не коммитить ключ**. Указанный URL должен быть совместим с выбранным протоколом; собственные API Anthropic/Google без совместимого шлюза пока не реализованы.

Для домашнего сервера через **SSH-туннель** безопаснее использовать локальный адрес в профиле:

```bash
ssh -L 11435:127.0.0.1:11434 USER@YOUR_SERVER
```

Затем в отдельном терминале установите `base_url = "http://127.0.0.1:11435"`, `provider = "ollama"`. Такая схема не требует открытия Ollama для всего интернета. Для прямого подключения к серверу по HTTPS требуется `allow_remote = true`. Незашифрованный HTTP вне `localhost` дополнительно требует `allow_insecure_http = true` и не рекомендуется.

**Приватность:** при включённом AI выбранному серверу отправляются команда и часть её вывода. Перед отправкой работает ограниченная маскировка распространённых секретов; она **не может гарантированно удалить любые конфиденциальные данные**. Для чувствительных задач используйте `/ai off` и только локальный доверенный сервер. URL и секреты не пишутся в отчёты. Любая модель получает вывод как недоверенные данные, не как команды к исполнению.

При интерактивном запуске **Codex CLI** приложение больше не принуждает Codex работать в режиме `tui.alternate_screen="always"` — такой режим на Mac пользователя отличался от привычного интерфейса в обычном терминале. Вместо этого без изменения `~/.codex/config.toml` только текущий запуск использует `--no-alt-screen`: Codex рисует привычный **inline-интерфейс** с приветственным экраном, меню и полем ввода. Terminal-AI-CLI временно открывает для него **чистый отдельный экранный буфер**, чтобы старые строки `git pull` не находились над Codex, а после закрытия возвращает свою ленту блоков. Явные пользовательские настройки `--no-alt-screen` и `tui.alternate_screen` не переписываются. Прокрутку трекпадом в Terminal.app нужно отдельно проверить на macOS: это решение подтверждено только имитацией интерактивного приложения в Linux/PTY, но не реальным Codex CLI на Mac.

## Прокрутка в Terminal.app (macOS)

**Ограничение macOS:** Terminal.app может прокручивать собственный основной scrollback **даже когда программа открыта в alternate screen**. Поэтому предыдущий `?1049h` не гарантировал скрытие строк `Last login` и `git pull` при движении трекпадом. Это поведение самого Terminal.app, а не блоков приложения.

Чтобы прокрутка не показывала старый вывод, открой **Terminal → Settings → Profiles → Keyboard** и включи **Scroll alternate screen** для текущего профиля. Прокрутка будет направляться в интерактивную программу; для просмотра блоков Terminal-AI-CLI надёжно работают **PageUp / PageDown**. Если Terminal передаёт события колеса мыши, приложение прокручивает **свои блоки**, не изменяя строку ввода. Конкретная реакция трекпада зависит от версии Terminal.app и настроек профиля — поведение надо проверить на macOS.

Содержимое scrollback **не удаляется**. Мы намеренно не отправляем `CSI 3J`, поскольку это очищает доступную в окне историю обычного Terminal. Для полностью чистого буфера можно открыть отдельную новую вкладку Terminal, а не удалять старую историю. Пользователям iTerm2 может дополнительно понадобиться включить `Report mouse wheel events` в настройках профиля.

## Разработка и проверки

```bash
python3 -m unittest discover -s tests -v
python3 -m terminal_ai models
python3 -m terminal_ai run -- /bin/echo hello
```

Прямой TUI обязательно проверить **на реальном macOS Terminal.app/iTerm2**, особенно размеры, обновление, Ctrl+C, `/raw codex` и перенаправления ввода. Linux-тесты не подтверждают Mac-совместимость.
