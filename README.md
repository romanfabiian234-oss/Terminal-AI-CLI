# Terminal AI CLI

Лёгкий локальный терминал с лентой блоков в духе Codex CLI: **объяснение выше, исходный технический вывод ниже**. Исходный вывод остаётся доступен. Блоки не дублируются при обновлениях. Это **ранняя тестовая версия v0.1**, а не замена полноценному эмулятору терминала.

## Что уже работает

- Терминальный TUI на `curses` без сторонних runtime-зависимостей: команда, статус, короткое объяснение, свёрнутый вывод, просмотр истории.
- Запуск реальных команд через PTY. Вывод обновляется по мере появления; ошибка определяется по коду завершения, а не по догадке модели. Пока команда выполняется, результат не объявляется успешным или ошибочным. В блоках `PAGER=cat` и `GIT_PAGER=cat` отключают интерактивный просмотрщик Git; для него остаётся `/raw`.
- **Несколько команд подряд:** вставленные или быстро введённые строки попадают в очередь (до 32 команд) и выполняются по порядку, каждая в своём блоке. Пока выполняется команда, строка ввода остаётся доступной; `Ctrl+C` прерывает текущую и очищает очередь. Для передачи ввода активной программе (например, `read`) нажмите `Ctrl+G`, для полноценного интерактивного TUI — используйте `/raw COMMAND`.
- **Экспериментальная постоянная сессия** `/session on`: отдельные команды работают в одной Bash/Zsh-оболочке, сохраняются `cd`, переменные, функции и алиасы. На Linux/Bash прошла тестирование; macOS/Zsh ещё нужно проверить.
- Мгновенные объяснения стандартных действий через правила: `ls`, `pwd`, `date`, `git status` и `git log` не вызывают модель без необходимости. Опциональные объяснения локального ИИ и fallback при недоступном сервере.
- **Произвольные модели через Ollama** и модели на **OpenAI-совместимых HTTP API** (например, LM Studio, llama.cpp, vLLM). Сервер может быть на Mac, домашней машине или удалённым.
- Разные профили и переключение командой `/model`; ключи API только из переменных окружения, HTTPS для удалённых серверов по умолчанию.
- `/raw COMMAND` открывает интерактивные полноэкранные программы, включая Codex CLI, в обычном терминале без порчи изображения; после их завершения итог попадает в блок истории. Во время `/raw` AI-пояснения внутри полноэкранного интерфейса **пока не выводятся**.
- История выводов хранится **только в RAM** в ограниченных буферах; нет телеметрии, встроенного облачного сервиса и автоматического выполнения AI-команд.

## Установка (macOS)

Требуется Python **3.11+**, macOS и встроенный `/bin/zsh`. Для базовой версии не требуется установка Rust, tmux или Ollama (если AI отключён).

```bash
# Из папки, в которую удобно клонировать проекты:
git clone https://github.com/romanfabiian234-oss/Terminal-AI-CLI-.git
cd Terminal-AI-CLI-
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
terminal-ai init
terminal-ai doctor
terminal-ai
```

Для локального ИИ отдельно установите и запустите Ollama и загрузите нужную модель:

```bash
ollama pull qwen3.5:2b
```

Если Python 3.11+ отсутствует, установите актуальный Python отдельно. Не запускайте скрипты установки с неизвестных сайтов.

`terminal-ai` — новая программа внутри обычного терминального окна (Terminal.app, iTerm2, Ghostty). Она **не заменяет системный Terminal.app**.

## Управление

Команды приложения начинаются с `/`, как в Codex CLI. Старый префикс `:` временно сохраняется для совместимости. Обычные пути, например `/bin/echo`, выполняются как команды оболочки.

`/explain` создаёт **новый видимый блок** с ответом ИИ о последней выполненной команде; при отсутствии связи с моделью показывает ошибку, а не молчит.

| Действие | Команда |
| --- | --- |
| Помощь | `/help` |
| Постоянная оболочка (экспериментально) | `/session on` / `/session off` |
| Список профилей | `/models` |
| Выбор модели/сервера | `/model local` или `/server home` |
| Повторно объяснить последнюю операцию | `/explain` |
| Язык новых объяснений | `/language ru`, `/language uk`, `/language en` |
| Включить или выключить ИИ | `/ai on` / `/ai off` |
| Развернуть технический вывод последнего блока | `Ctrl+T` или `/expand` |
| Прокрутить ленту | `PageUp` / `PageDown` |
| Очистить историю в RAM | `Ctrl+L` или `/clear` |
| Прямой PTY-режим для TUI | `/raw codex` / `/raw vim` |
| Перейти в другую папку | `cd path` |
| Выйти | `/exit` или `Ctrl+D` на пустой строке |

Во время обычной выполняемой команды ввод **не передаётся** ей автоматически: новый текст считается следующей командой и попадает в очередь. `Ctrl+G` переключает прямую передачу ввода/очередь; `Ctrl+C` прерывает процесс и очищает очередь. `/raw` даёт дочерней программе прямое управление экраном; по завершении следует нажать Enter для возврата к ленте.

**Ограничения:** по умолчанию каждая обычная команда запускается в отдельной сессии `zsh -lc`; сохраняется `cd`, но не переменные, функции и алиасы между такими командами. При `/session on` запускается **постоянная** интерактивная `zsh -ic` (или выбранная оболочка), где сохраняется состояние; сейчас принимаются только **однострочные команды**, а shell-режимы Bash и Zsh могут отличаться. Проверено с Bash на Linux, но не с Zsh на macOS. В экспериментальной сессии `Ctrl+C` завершает внешнюю foreground-программу сигналом `SIGTERM` (не `SIGINT`), чтобы сохранить состояние оболочки; при прерывании shell builtins она всё ещё может завершиться. В режиме `/raw` запускается отдельная интерактивная программа, не использующая состояние предыдущей сессии. Для сложных полноэкранных TUI ещё нет надёжной реконструкции визуальных действий. Полное объединение пояснений с внутренними блоками Codex — следующий этап, не готовая функция.

## Подключение моделей и сервера

Файл: `~/.config/terminal-ai/config.toml` (создаётся через `terminal-ai init`). Пример:

```toml
[app]
language = "ru"
shell = "/bin/zsh"
max_blocks = 100
max_output_lines = 400

[models]
active = "local"

[models.local]
provider = "ollama"
base_url = "http://127.0.0.1:11434"
model = "qwen3.5:2b"

[models.home]
provider = "openai"
base_url = "https://my-ai-server.example/v1"
model = "any-model-on-server"
api_key_env = "TERMINAL_AI_KEY"
allow_remote = true
```

`provider = "ollama"` использует `/api/chat`; `provider = "openai"` использует `/chat/completions`. API-ключ указывать через `export TERMINAL_AI_KEY=...` **на своём Mac, не коммитить ключ**. Указанный URL должен быть совместим с выбранным протоколом; собственные API Anthropic/Google без совместимого шлюза пока не реализованы.

Для домашнего сервера через **SSH-туннель** безопаснее использовать локальный адрес в профиле:

```bash
ssh -L 11435:127.0.0.1:11434 USER@YOUR_SERVER
```

Затем в отдельном терминале установите `base_url = "http://127.0.0.1:11435"`, `provider = "ollama"`. Такая схема не требует открытия Ollama для всего интернета. Для прямого подключения к серверу по HTTPS требуется `allow_remote = true`. Незашифрованный HTTP вне `localhost` дополнительно требует `allow_insecure_http = true` и не рекомендуется.

**Приватность:** при включённом AI выбранному серверу отправляются команда и часть её вывода. Перед отправкой работает ограниченная маскировка распространённых секретов; она **не может гарантированно удалить любые конфиденциальные данные**. Для чувствительных задач используйте `/ai off` и только локальный доверенный сервер. URL и секреты не пишутся в отчёты. Любая модель получает вывод как недоверенные данные, не как команды к исполнению.

## Разработка и проверки

```bash
python3 -m unittest discover -s tests -v
python3 -m terminal_ai models
python3 -m terminal_ai run -- /bin/echo hello
```

Прямой TUI обязательно проверить **на реальном macOS Terminal.app/iTerm2**, особенно размеры, обновление, Ctrl+C, `/raw codex` и перенаправления ввода. Linux-тесты не подтверждают Mac-совместимость.
