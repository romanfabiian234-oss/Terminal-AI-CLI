# Terminal-AI-CLI — план разработки

## Состояние реализации — 2026-11-24 (проверяемый прототип v0.1)

Реализован [прототип на Python 3.11+](README.md) с локальным PTY, curses, блоками действий, сворачиванием исходного вывода, правилами и потоковыми адаптерами Ollama/OpenAI-compatible. Для первой версии выбран Python stdlib вместо Rust: он позволяет провести реальную локальную проверку с минимальным количеством зависимостей. Rust остаётся возможным этапом после измерений производительности; старое описание Rust/tmux ниже — исходная архитектурная идея, **не утверждение о реализованном коде**. Проверки и ограничения: [отчёт](reports/2026-11-24-mvp.md).

Дополнительный экспериментальный этап реализован: `:session on` запускает постоянную Bash/Zsh-сессию в PTY, сохраняет переменные, алиасы, функции и папку. 20 локальных тестов PASS на Linux/Bash; **на macOS/Zsh не проверено, gate не принят**. Отчёт: [этап 2](reports/2026-11-24-persistent-shell.md). Далее необходимы macOS-проверка, безопасная интеграция структурированных событий Codex, выбор серверов/моделей и нагрузочные измерения. Нельзя считать интерфейс Codex TUI полностью совместимым с блочным режимом до доказательной проверки.

## 1. Назначение
Локальный помощник для терминала macOS Apple Silicon. Единая вертикальная лента в стиле Codex CLI: объяснение фактического действия простым языком сверху, соответствующий технический вывод снизу. Внизу — ввод команд. Не переводить каждую строку. Объединять связанные действия, выделять результаты, ошибки и неизвестные состояния. Не выполнять команды от имени пользователя.

## 2. MVP и UX
- Команда `terminal-ai` запускает интерактивную оболочку внутри PTY. Основной режим — единая вертикальная лента, НЕ две панели.
- Блок операции: индикатор статуса, короткое название, объяснение в 1–2 предложениях, команда (если известна), затем приглушенный технический вывод с отступом. Длинный вывод сворачивается до 2–4 строк с количеством скрытых строк. Ошибки и предупреждения не прятать полностью.
- Пример:
  ```text
  ● Проверка цифровой подписи
    Система обновила подписи компонентов MapleBar.
    └ replacing existing signature
      --validated: Updater.app
      +12 lines (развернуть)

  ● Приложение успешно создано
    Сборка завершена. Отправлена команда открытия приложения.
    └ Created MapleBar.app
      Opening the app.

  ❯ ~/MapleBar-Test %
  ```
- Блок появляется сразу, без ожидания модели: статус выполнения и технический вывод видны сразу, пояснение добавляется над выводом в том же блоке по готовности. Потоковое обновление без повторной вставки блока; не перескакивать к концу при чтении старой истории.
- Группировка по командам и смысловым этапам внутри длинной команды; выходной код, факты и время сохраняют связь с соответствующим блоком. Не смешивать соседние операции.
- Раскрытие/сворачивание вывода клавиатурой и мышью, копирование исходных строк, пауза ИИ, вопрос о выбранном блоке, переключение языка и модели. Сочетания клавиш настраиваемые, не перехватывать стандартные сочетания оболочки в режиме прямого ввода.
- Внизу — активная строка ввода и компактный статус модели. Поддерживать историю, Ctrl-C, resize, обычные цвета и прокрутку. Не изменять пользовательский .zshrc без согласия.
- Для полноэкранных интерактивных программ (vim, htop, Codex CLI и т. п.) предусмотреть отдельный режим прямого PTY passthrough с сохранением поведения программы, а после выхода восстановить ленту. Не обещать произвольное добавление блоков внутрь чужого TUI; анализ видимых изменений или поддерживаемых структурированных событий — отдельный адаптер. Не вмешиваться в запросы пароля.
- При отсутствии модели терминал работает, правила продолжают объяснять известные события. Приватный режим отключает захват для анализа.
 
## 3. Архитектура
Shell/PTY -> Event Capture -> VT parser + shell hooks -> Smart Filter -> Rule Engine OR Local LLM -> Block Store -> Ratatui unified timeline.
- MVP: управляемый дочерний PTY, двунаправленная передача ввода и вывода, resize и корректное завершение. В режиме ленты приложение владеет экраном и размещает блоки самостоятельно, не вставляя текст ИИ в поток дочернего процесса. Захват только своей сессии. События shell hooks — отдельный локальный канал с ограниченными правами. Не записывать необработанные данные на диск. Сначала реализовать обычные команды; полноценный passthrough и совместимость интерактивных TUI тестировать отдельно.
- Zsh preexec/precmd в оболочке проекта сообщают о начале/окончании команды и exit status через отдельный локальный канал. Bash — позднее. Внутри сторонних интерактивных TUI границы операций определяются из доступных событий/видимого вывода, не выдаются за достоверные exit codes. Возможен отдельный адаптер структурированных событий Codex, когда поддерживаемый интерфейс подтвержден.
- Парсер VT/ANSI учитывает частичные UTF-8 последовательности, carriage return, курсор, очистку экрана, альтернативный буфер, обновления прогресса. Для TUI анализировать изменившиеся видимые строки, а не просто удалять ANSI.
- Нормализация: session_id, event_id, timestamp, command (при наличии), category, output_excerpt, exit_code (optional), status, evidence, confidence.
- Дедупликация в пределах операции, группировка по границам команд или паузе 200–400 мс, обновление прогресса не чаще 1 раза/сек. Ошибки и завершения приоритетны. Ограничить буферы и очереди; объединять низкоприоритетные события под нагрузкой. Никогда не блокировать основной терминал ради ИИ.
- Rule Engine: точные шаблоны Git, npm, cargo, swift build, codesign, tests; проверять контекст. Exit code 0 означает завершение процесса без ошибки, не гарантирует отсутствие всех проблем. Без подтверждения результат неизвестен.
- Локальный LLM получает только новые отфильтрованные фрагменты, краткое состояние операции и доказательства. Не копировать весь лог. Пример: «Обновлена подпись приложения, проверены компоненты. Приложение создано; запрошено открытие».
- Асинхронный inference worker, одна генерация за раз, потоковый вывод, отмена устаревшего анализа; UI и сбор вывода независимы. При отказе backend — правила и сообщение о недоступности модели.
- Без облачного fallback, телеметрии или автоматического исполнения команд. Логи считаются недоверенными данными, а не инструкциями. Маскировать секреты до передачи модели и истории; исключить ввод клавиш/паролей, скрывать чувствительные команды, отключать захват в приватном режиме. История по умолчанию только в RAM; сохранение отдельно по согласию. Секреты невозможно гарантированно обнаружить, поэтому предусмотрена пауза и отключение захвата.

## 4. Стек
Rust, Tokio, Ratatui/Crossterm, PTY (кандидат portable-pty), VT parser (выбрать по тестам), serde, TOML. tmux не требуется для основного режима. Ollama local HTTP API на loopback — первый backend. MLX/MLX-LM — альтернативный backend после сравнения на реальном Mac. Использовать готовые PTY/VT-библиотеки; не писать полноценный эмулятор терминала или inference engine с нуля.
- Instant: детерминированные правила без модели.
- Fast: Qwen3.5-2B quantized; запасной кандидат 0.8B при достаточном качестве.
- Deep: Qwen3.5-4B или установленная пользователем модель по запросу.
- Не загружать две модели постоянно. Прогревать основную по выбору, выгружать при длительном простое/ограничении ресурсов. Не останавливать другие приложения.
- Стартовые параметры: think=false, stream=true, temperature=0.1–0.2, num_ctx=2048–4096, num_predict=64; для подробного режима увеличить лимит. Настройки проверять для конкретного backend. Цель ответа — 1–2 предложения: действие, результат, если нужно — причина/неопределенность.
- Ollama model: https://ollama.com/library/qwen3.5:2b
- PTY candidate: https://docs.rs/portable-pty/latest/portable_pty/
- Ratatui: https://docs.rs/ratatui/latest/ratatui/

## 5. Структура
```
Cargo.toml
src/
  main.rs           # CLI, lifecycle
  session.rs        # PTY lifecycle, resize, passthrough
  capture.rs        # transport and shell events
  terminal.rs       # VT state and screen deltas
  events.rs         # event types
  filter.rs         # batching/dedup/redaction
  rules.rs          # deterministic explanations
  inference.rs      # trait and queue
  ollama.rs         # local backend
  ui.rs             # Ratatui unified timeline
  blocks.rs         # block state, evidence, folding
  config.rs
rules/
  git.toml
  build.toml
  tests.toml
tests/
  fixtures/
  integration/
docs/
  benchmarks.md
config.example.toml
PLAN.md
```
Do not create empty modules until needed.

## 6. Этапы
- [ ] 0. Создать Rust CLI, конфигурацию, проверки зависимостей, CI (cargo fmt/clippy/test), локальный запуск.
- [ ] 1. PTY launcher и единая лента блоков; ввод, resize, Ctrl-C, завершение сессии, восстановление режима терминала; захват только своей сессии. Проверить passthrough отдельно.
- [ ] 2. VT parser, Zsh hooks, группировка, ограниченные буферы, редактирование секретов, базовые правила. Проверить реальный Codex CLI и интерактивные программы.
- [ ] 3. Ollama streaming backend, прогрев, таймаут, отмена, короткие русские объяснения и fallback. Проверить 0.8B/2B/4B на одинаковых логах.
- [ ] 4. UI: объяснение над техническим выводом, статусы, обновление блоков на месте, раскрытие и копирование вывода, пауза ИИ, ручной подробный запрос, режимы, стабильная прокрутка и ввод. Проверить отсутствие дублирования при обновлении и resize.
- [ ] 5. Производительность и надежность: замеры, обработка большого вывода, неправильных escape-последовательностей, недоступной модели, смены размеров, секретов, prompt injection, пробуждения Mac. Проверить отсутствие зависаний и дублирования.
- [ ] 6. Релиз v0.1: сборка arm64, инструкции установки/удаления, release artifact; модель загружается отдельно.
- [ ] 7. v0.2+: MLX backend при измеримом выигрыше, опциональный структурированный адаптер Codex, Bash, история по выбору, мониторинг ресурсов, поддержка нескольких сессий.

## 7. Целевые метрики (не результаты тестов)
MacBook Air M5 16 GB, прогретая модель, короткие отфильтрованные события: правило p95 до 50 мс; первый токен p50 до 1 с; объяснение 1–3 с как целевой ориентир; Rust helper до 100 MB RSS без учета дочерней оболочки/model runtime; суммарная дополнительная память модели/помощника — стремиться к 4 GB; idle CPU до 1%. Замерить p50/p95 end-to-end, RAM peak, CPU, энергопотребление, очереди, частоту ошибочных объяснений, отдельно холодный запуск. Использовать одинаковый набор минимум 50 примеров: сборка, тесты, Git, codesign, неизвестные ошибки, TUI перерисовки. Проверить русский язык, отсутствие выдуманного успеха/причины, сохранение терминальной отзывчивости, отсутствие исходящих сетевых запросов после установки модели. Цель — >=95% корректных кратких объяснений на фиксированном тестовом наборе; при низкой уверенности сообщать, что данных недостаточно.
- При конфликте скорости и точности не выдумывать объяснение. Если 2B не укладывается в цели, оптимизировать фильтр и измерить 0.8B/другую квантизацию; если качество недостаточно, повысить размер модели по выбору.
- Первый релиз считается готовым после проверки ключевых сценариев на macOS и документирования ограничений.

## 8. Не входит в MVP
Самостоятельное выполнение команд, облачные запросы, чтение других окон или клавиатуры, OCR, глобальный мониторинг системы, обучение собственной модели, полноценный собственный эмулятор терминала, графический macOS-клиент, режим двух панелей.
