## Выполненный этап

- Простые `cd` корректно изменяют рабочую папку. `cd -` меняет её обратно; `cd -- PATH` и кавычки для пробелов поддерживаются.
- Составные команды, кавычки с shell-спецификой, подстановки, редиректы, пайпы и специальные формы `cd` не теряются при перехвате — они исполняются обычным Zsh.
- Отдельный `:` остаётся shell-builtin, а не внутренней командой приложения.
- История ввода ограничена последними 1000 строками, без записи на диск.
- Очередь ИИ при завершении приложения перестаёт принимать новые задания, фоновый worker получает сигнал остановки.
- Добавлены регрессионные тесты shell-семантики, границ истории, закрытия ИИ и автономного CLI.

## Обнаружено при ручной приёмке · Ctrl+C

На macOS Terminal.app при `Ctrl+C` приложение завершалось с `KeyboardInterrupt` из `curses.get_wch()`; это **подтверждённая проблема**, препятствующая ежедневному использованию. В текущем PR добавлена обработка сигнала `SIGINT` внутри главного цикла и резервная обработка `KeyboardInterrupt` при чтении клавиатуры; добавлены пять регрессионных тестов. **Новая версия ещё не проверена на Mac**. При первом запуске новых 162 тестов пользователь получил **1 ERROR**: искусственный `Mock` ошибочно направил тест сигналов в полноэкранный путь и вызвал `curses.endwin()` вне реального curses-экрана. Тестовый объект исправлен в `f3e72e5` (явный `raw_command = ""`). Обработчик `Ctrl+C` не изменён. Требуется повторный полный прогон и реальная проверка `sleep 10` → `Ctrl+C` → `echo ready`. Предыдущий успешный результат `157 tests, OK (skipped=5)` относится к коду до исправления и не подтверждает новый обработчик.

## Реальная проверка Ctrl+C и улучшение статуса

25.11.2026 пользователь показал в Terminal.app результат `sleep 10` после `Ctrl+C`: процесс завершился с **exit code -2 (SIGINT)**, а Terminal-AI-CLI **остался открытым**. Это подтверждает устранение прежнего вылета с `KeyboardInterrupt`. Продолжение работы командой `echo ready` после прерывания на данном скриншоте не показано.

Выявлен UX-недостаток: прерывание показывалось красной ошибкой, а автоматический ИИ Qwen3.5:2B тратил 1.61 с на объяснение ожидаемого сигнала. Новое исправление помечает **только команды, для которых пользователь нажал Ctrl+C и получен ненулевой код**, статусом `interrupted` и текстом «Команда прервана», пропускает автоматический запрос к модели. Обычные сбои по ненулевым кодам остаются ошибками, код процесса сохраняется. Добавлены 4 регрессионных теста. **Новые тесты и UX-изменение ещё не проверены пользователем на Mac.**

**Повторный unittest на Mac (состояние до исправления):** на `2199f20` выполнены 166 тестов, **1 FAIL, 5 skipped**. Единственный FAIL связан с устаревшим утверждением `status == "error"` в `test_session.py`: пользовательское прерывание теперь корректно помечено `interrupted`. Тест дополнен проверкой статуса, ненулевого кода и заголовка (`15a4c46`), полноценный повторный запуск пока **NOT VERIFIED**.

## Обязательные критерии повседневного использования

| Сценарий | Критерий | Состояние |
| --- | --- | --- |
| Установка/запуск | `doctor`, `models`, `run -- /bin/echo hello`, штатный вход/выход | NOT TESTED на новой ветке |
| Обычные команды | `pwd`, `ls`, `git status`, ошибки exit code, пайпы/редиректы без потери команд | NOT TESTED |
| Навигация | `cd`, `cd -`, папки с пробелами, составные команды и отсутствие ложной смены cwd | NOT TESTED на Mac |
| Состояние оболочки | Переменные, функции, алиасы, `cd` и прерывание сохраняют ожидаемую семантику | BLOCKED: `/session on` не принят на macOS |
| Редактирование | Стрелки, Home/End, Delete, клик, Tab, кириллица, длинные строки, изменение окна | PARTIAL: основные сценарии проверены на старом SHA |
| Вставка и отмена | Многострочная вставка ничего не запускает сама; Ctrl+C отменяет очередь | NOT TESTED вручную на новой ветке |
| Вывод/прокрутка | ANSI, длинные выводы, переход в начало/конец, `⌘K` без потери истории | PARTIAL |
| Полноэкранные приложения | `vim`, `nano`, `codex` и `/raw`: экран, клавиши, resize, выход и возврат | NOT TESTED на реальном Codex/Mac |
| ИИ и отказоустойчивость | Работает без модели, недоступный сервер не блокирует ввод, конфиденциальные данные не передаются без выбора профиля | PARTIAL: unit tests, нет полной macOS-приёмки |
| Долгая работа | Несколько часов, большой вывод, устойчивое потребление памяти/CPU, корректное закрытие | NOT TESTED |
| Релиз/обновление | Установка, откат, чистый diff, независимое review без блокирующих проблем | NOT ACCEPTED |

**Важно о Zsh:** в текущем обычном режиме `cd DIR && pwd` выполняется как один shell-вызов, но изменение папки в этом дочернем процессе **не сохраняется для следующей команды**. Аналогично `export VAR=...` не переживает следующий изолированный вызов. Это полноценная shell-функция только в экспериментальном `/session on`. До перехода в повседневный режим без оговорок нужна независимая проверка постоянной Zsh-сессии и согласованное решение по режиму по умолчанию.

## Проверка владельцем на macOS (безопасная)

В новой ветке после активации `.venv`:

```bash
python3 -m unittest discover -s tests -q
python3 -m terminal_ai doctor
python3 -m terminal_ai models
python3 -m terminal_ai run -- /bin/echo hello
terminal-ai
```

Внутри `terminal-ai` вводить по одному: `pwd`, `cd /tmp`, `pwd`, `cd -`, `pwd`, `cd /tmp && pwd`, `seq 1 150`. Важно: `cd /tmp && pwd` должен показать `/tmp` в результате, но текущая папка приглашения сохранится. Проверить увеличение/уменьшение окна, скролл, `⌘K`, левый клик для редактирования, многострочную вставку `pwd\ndate` с подтверждением каждой строки. Затем `sleep 10`, Ctrl+C, `echo ready`, `/exit`.

Экспериментальные `/session on` и интерактивный Codex испытывать отдельно, с безвредными командами. Не проводить в этой проверке операции удаления данных, публикации, установки компонентов или изменения настроек оболочки.

**Gate выпуска:** актуальные результаты macOS + независимое code review + отсутствие критических незакрытых проблем + одобрение владельца. До этого приложение можно использовать как тестовый дополнительный терминал, **не** как гарантированную замену Terminal.app.
